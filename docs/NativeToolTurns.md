# 네이티브 도구 턴과 관측 전달

ServiceModel은 현재 사용자 또는 로드된 스킬의 `Use`, `Call`, `Invoke` 명령으로 입력이 시작하고 공개된 도구를 명시할 때, 아직 시도하지 않은 첫 도구를 네이티브 `required` 선택으로 전달한다. 문장 시작과 First/Then 순서만 대상으로 하며 일반 언급이나 부정문, 인용·코드·문자열 인자, 도구 결과는 실행 명령으로 승격하지 않는다. 도구를 한 번 시도한 뒤에는 다음 명령으로 진행한다. 명시적인 호스트의 `none`/`required` 설정은 보존한다.

`Read secret.txt`처럼 실제 파일·경로가 바로 뒤따르는 직접 읽기 명령도 같은 계약으로 전달한다. `Read about ...`와 인용된 예시는 자동 선택을 유지한다. 도구 목록에 Read가 없거나 이미 시도했으면 추가 호출을 강제하지 않는다.

이는 모델에게 올바른 호출 형태와 순서를 제공하는 생성 계약이다. 실제 실행은 기존 ToolRunner의 권한, 인자 검증, 취소 및 훅을 모두 거치며 도구 결과를 만들어 내거나 모델 답변을 기대값으로 교체하지 않는다. 측정과 생성은 같은 요청 변환을 사용한다.

관측은 `text`, `is_error`, `data`를 보존하는 JSON이다. 원문 text를 첫 필드에 배치하여 부가적인 경로·해시와 혼동하지 않도록 한다. 스킬의 작업 디렉터리와 스킬 자체의 리소스 디렉터리는 구별한다.

명시적인 단일 도구 순서는 병렬 호출 없이 생성한다. 같은 쓰기 도구를 반복한 호출 배열이 출력 한도까지 생성되는 현상을 방지하며, 실행기의 병렬 처리 능력이나 전체 호출 수 제한은 바꾸지 않는다.

현재 입력이 정확한 파일 내용 또는 단일 관측값을 요청했다면 완료 응답이 실제 관측을 포함하는지 검증한다. 실패하면 해당 도구 결과에서 가져온 값을 JSON 문자열 데이터로 재제시하여 모델에 수정을 요구한다. 관측을 답변으로 직접 교체하지 않으며 재생성도 원래 maxTurns와 토큰 제한을 소비한다. 부분 읽기·실패한 관측과 도구 정의 검색 결과는 근거로 사용하지 않는다. 이 피드백은 새 사용자 지시로 취급하지 않는다.

service_model 회귀 검사는 순차 호출, 관측을 통한 재호출 유도 차단, 부정문, 호스트의 none 설정, 원문·구조 데이터·실패 상태의 손실 없는 전달을 검증한다. agent 회귀 검사는 잘못된 해시 응답의 수정과 기존 턴 제한의 준수를 검사한다. 실제 추론 검사는 기존 모델, 출력 토큰 및 턴 제한으로 별도 검증한다.

관측값 복사 오류를 수정하는 턴은 추가 실행이 필요 없는 응답 생성 단계이므로, 호스트 선택이 auto인 경우 도구를 다시 공개하지 않는다. 기존 권한·턴 한도·출력 한도는 유지한다. 명시적인 호스트 도구 선택은 덮어쓰지 않는다.

복사 수정 요청은 원래 시스템 계약·사용자 목표·실제 관측값만으로 별도 생성 입력을 구성한다. 잘못된 이전 복사 결과를 반복 예시로 강화하지 않기 위함이다. 원래 대화와 모든 실패·수정 기록은 세션에 보존하며, 측정과 생성에 동일한 입력을 사용한다.

사용자가 병렬·동시 실행을 명시한 입력은 단일 호출 순서로 강제하지 않고 기존 병렬 도구 선택을 유지한다.

`exact description`처럼 JSON 문자열 필드를 명시한 요청도 같은 검증 경로를 사용한다. 실제 결과의 중첩 객체·배열에서 해당 필드가 유일할 때만 복사 근거로 삼으며, 여러 후보가 있으면 임의로 선택하지 않는다. 회귀 검사는 중첩 필드와 모호한 다중 후보를 모두 검사한다. 일반 시스템 프롬프트는 기존 계약을 유지하며 이 검증을 요청하지 않은 대화에는 추가 복사 지시를 주입하지 않는다.

`return only`가 포함된 원문 복사 요청은 값의 포함 여부뿐 아니라 응답 전체의 동일성을 검증하여 서문·따옴표·코드 펜스가 추가되는 오류도 같은 턴 예산 안에서 수정한다.

단일 값 복사에서 원문 text가 단일 문자열 필드의 JSON이면 그 디코딩된 값을 사용한다. 전송 프로토콜의 별도 metadata 필드로 원문 값을 대체하지 않는다. 이 우선순위도 회귀 검사에 포함한다.

작은 모델이 복사 대상의 JSON 구분자까지 반복하는 경우를 막기 위해, 네이티브 ServiceModel의 복사 수정 턴은 관측 문자열을 enum으로 갖는 단일 value 속성의 JSON 스키마로 생성한다. 모델이 실제 생성한 JSON을 파싱하고 관측과 일치하는지 검사한 후 그 문자열을 반환한다. 잘못된 생성 결과를 관측값으로 대체하지 않는다. 내부 JSON 델타는 보류하고 검증된 문자열을 내보내므로 외부 스트림과 최종 문자열도 일치한다. 명시적인 호스트 응답 스키마는 유지하며, 기존 토큰·턴 제한과 취소는 계속 적용한다.

현재 지시가 실제로 실행된 완전한 관측의 값만 요구하면 추가 도구를 공개하지 않고 같은 구조화 복사 경로로 최종 응답을 생성한다. 명시적인 반복 명령은 도구 이름별 호출 횟수로 구분하고, once로 제한한 명령은 해당 결과를 받은 뒤 재실행하지 않는다. 과거에 읽은 파일 내용을 다시 묻는 요청은 기록된 Read 인자·실제 결과를 파일 경로로 연결하여 재사용하며, 동명 파일이 모호하면 임의로 선택하지 않는다.

명시적인 with·for·set 필드명 형식의 단일 도구 요청은 필수 속성과 지시문에 명시한 선택 속성만 모델에 공개한다. 인용된 값 속 필드명은 선택 근거로 쓰지 않는다. 복합 스키마·호스트의 명시적 선택은 그대로 두며, 실행기는 원래 스키마와 권한을 계속 검증한다. 이 방식은 요청하지 않은 expectedRevision이나 metadata를 모델이 추측해 추가하는 것을 방지한다.

로드된 스킬은 문장 앞에 작업 문맥을 둘 수 있으므로, 실제 스킬 본문의 문장 경계에서 시작하는 명시적 도구 명령도 순서 계약으로 처리한다. 일반 사용자 설명문과 인용 예시·부정문은 이 예외를 적용하지 않는다.

정확한 값을 최종 응답으로 반환하라는 명시적 지시는 only 표현 유무와 관계없이 실제 관측을 얻고 명시된 도구 순서를 마친 뒤 복사 생성으로 완료한다. 도구 정의 검색만으로는 완료하지 않는다.

with·for·set·and 뒤의 필드에 리터럴 값이 명시되면 해당 속성의 생성을 필수로 요구한다. 선택 속성의 누락으로 일부 갱신만 수행되는 것을 방지하기 위함이다. 값 자체를 실행기에 주입하거나 권한·원래 스키마를 대체하지 않는다.


## 명시적 경로와 사용자 정의 모델의 JSON 결과

현재 사용자 입력 또는 실제로 로드된 스킬의 `Read` 명령에 파일 경로가 명시되어 있으면, 해당 네이티브 요청의 `path` 스키마에 그 경로를 전달한다. 연속 명령은 이미 시도한 호출 수에 따라 선택하며, 스킬 리소스 디렉터리나 인용된 예제를 작업 파일로 대체하지 않는다. 기존 호스트 경로 제약과 충돌하면 제약을 확장하지 않는다. 원본 레지스트리와 실행 권한 검사는 유지한다. 계획 모드의 `Write`와 `Edit`에는 세션 소유의 계획 파일 경로만 게시하며 프로젝트 읽기는 유지한다.

사용자 정의 모델이 정확한 필드 요청에 JSON 객체를 반환할 때, 실제 생성 JSON 안에서 요청한 필드가 유일하고 실제 관측값과 일치하는 경우에만 해당 필드를 디코딩한다. 필드가 지정되지 않은 값 요청은 유일한 문자열 값만 허용한다. 틀린 값이나 다의적인 객체는 교정 절차와 기존 턴 제한을 따른다. 도구 결과를 답변으로 직접 대입하지 않는다.


메모리 통합의 완료 검증이 실패하면 실제 색인의 경로와 정규화된 중복 링크 대상을 피드백으로 제공한다. 먼저 현재 파일을 네이티브 Read로 다시 읽고 Edit로 수정하도록 지시하여, 잘못된 완료 문장만 반복하는 루프를 방지한다. 호스트가 색인을 직접 수정하거나 성공으로 대체하지 않으며, 원래 턴·컨텍스트·기한 및 읽기 선행·쓰기 권한 검사를 유지한다.


`Use the Read tool to read file.txt`처럼 도구 종류를 함께 적는 명시적 요청도 실제 파일 경로에 결합한다. 인용된 예제와 부정 지시는 이전과 같이 자동 호출이나 경로 권한으로 해석하지 않는다.


정확한 파일 내용 요청의 `content`와 `contents`는 같은 완료 계약을 사용한다. 완료된 도구 결과와 순차 호출 상태를 카탈로그 측정에도 보존하여, 더 이상 게시하지 않을 도구 정의 때문에 마지막 응답을 압축하려 하지 않게 한다. `content hash`·digest·checksum 요청은 파일 본문 복사로 바꾸지 않는다.
