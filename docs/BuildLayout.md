# 빌드와 테스트 자원 배치

컴파일 결과는 `build/`에 둔다. jsoncons, md4c, libyaml, Lexbor, tree-sitter 소스는 `resources/dependencies/`에 둔다. 이미 있는 소스는 그대로 재사용하고 불완전한 디렉터리는 덮어쓰지 않고 구성을 중단한다. 아직 없는 의존성은 기존의 고정 URL과 해시를 사용하는 CMake FetchContent가 준비한다.

CTest 출력과 임시 파일은 `resources/.state/`에 구성마다 고유한 경로로 두고 CTest fixture가 실행 전 준비하며 완료 후 정리한다. 한 구성에서 여러 CTest 프로세스를 동시에 실행하지 않는다. 하나의 CTest 실행 내 병렬 테스트는 지원한다. 강제 종료로 남은 작업 공간은 소유 여부를 확인한 뒤 정리한다.

네이티브 모델과 실제 에이전트·앱 실행은 단위 테스트 및 컴파일 검증과 별도로 기록한다.

공식 MCP 검증을 위한 외부 Python 환경의 바이트코드 준비는 기본 빌드에 포함되지 않는다. 필요한 경우 `iiMultimodalAgentMcpDependencyArtifacts` 타깃을 명시적으로 선택한다.

의사결정 게이트의 확률·기대값·오류 검사는 CTest용 C++ 실행 파일로
실행하며 Qt Test를 링크하지 않는다. 설치 소비자의 같은 검사도 별도로
Qt Test를 링크하지 않는다. 가짜 모델을 사용하는 의사결정 엔진 검사와
설치 소비자도 CTest에서 Qt Core 이벤트 처리만 사용한다. 다른 에이전트
검사의 Qt Test 의존성은 남아 있다.

메모리 통합 엔진의 가짜 모델·API·인프로세스 MCP 검사는 Qt Test 없이
CTest로 실행한다. 임시 프로젝트는 CTest fixture가 지정한 `resources/`의
임시 경로에 만들고 정리한다. 실제 모델 추론이나 외부 MCP 서버는 사용하지 않는다.

멀티모달 호스트 설정의 경로·별칭·오류 검사는 가짜 파일을 사용하는
CTest 실행 파일로 유지하며 Qt Test를 링크하지 않는다.

메모리 검색의 후보 필터·크기 제한·취소 검사는 격리된 가짜 프로젝트와
모델을 사용하며 CTest 실행 파일에서 Qt Test를 링크하지 않는다.

권한 요청과 세션 기록 엔진도 가짜 모델 및 격리된 상태로 CTest에서
검사한다. 세션 기록 시험의 임시 파일은 fixture의 `resources/` 경로에 둔다.

프로젝트 메모리의 읽기·쓰기·권한·경로 격리 검사는 임시 작업 공간에서
CTest로 실행하며 Qt Test를 링크하지 않는다.

멀티모달 콘텐츠의 검증·모델 라우팅·세션 복구 테스트와 설치 소비자는
가짜 모델을 사용하고 Qt Test 없이 CTest로 실행한다.

설치 소비자 CTest는 고유한 `resources/.state/consumer-*` 작업 공간을
준비·정리한다. 임시 입력과 출력은 소비자 빌드 디렉터리에 만들지 않는다.

메모리 검색 엔진의 자동·취소·API·인프로세스 MCP 검사는 가짜 모델과
격리된 테스트 자료를 사용하며 CTest로 실행한다.

의미 검색 테스트는 가짜 임베딩과 런타임을 사용해 출처·인덱스 갱신·
취소를 확인하며 Qt Test 없이 CTest로 실행한다.

스킬 권한의 승인 범위·복구·자식 실행 검사는 테스트용 스킬과 가짜
모델을 사용하며 Qt Test 없이 CTest로 실행한다.

메모리 추출 엔진의 백그라운드 작업·취소·API·인프로세스 MCP 검사는
가짜 모델과 fixture의 임시 경로를 사용해 CTest로 실행한다.

스킬 분기의 격리·실패·취소 검사는 테스트용 스킬과 가짜 모델을 사용하고
CTest 실행 파일에서 Qt Test를 링크하지 않는다.

세션 분기 검사의 복사·권한·실패 원자성·취소 케이스는 CTest로 실행한다.
파일 자료는 fixture가 관리하는 `resources/`의 임시 경로에 둔다.

프로젝트 메모리 엔진 검사의 결과는 Qt Test 전용 출력 파일 대신 CTest가
표준 출력과 종료 코드로 수집한다. 테스트는 가짜 모델과 격리된 자료를 사용한다.

세션 기록 검색과 설치 소비자는 CTest로 실행하며, 만료 검사의 대기 시간과
fixture가 지정한 `resources/` 임시 작업 공간을 유지한다.

메모리 통합의 잠금·복구·검증 테스트와 설치 소비자는 CTest에서 실행한다.
잠금 시험은 격리된 임시 경로에서 테스트 실행 파일의 자식 프로세스를 사용한다.

에이전트 프로필의 경계·모델 인가·가짜 백그라운드 작업 검사는 CTest가
표준 출력과 종료 코드로 수집하며 Qt Test 전용 출력 파일을 만들지 않는다.

멀티모달 서비스 검사는 CTest에서 기존 개별 음성 경계 케이스 선택을
유지한다. 이미지·오디오 fixture는 CTest의 임시 경로를 사용하며, 이 모듈의
설치 소비자 테스트 구성은 Qt Test 패키지를 찾거나 링크하지 않는다.

에이전트 컨텍스트·스킬·검색과 모델 훅의 기존 사례는 CTest 실행 파일에서
격리된 자료 및 가짜 모델로 확인하며 Qt Test를 링크하지 않는다.

파일 체크포인트의 복원·권한·손상 검사는 fixture의 임시 경로에서
CTest로 실행한다. 권한 설정 검사는 기존 패턴 자료를 소스 디렉터리에서
읽으며 실행 디렉터리나 Qt Test의 자료 탐색에 의존하지 않는다.

프로시저와 권한 요청 검사는 기존 타임아웃과 인프로세스 API·MCP 자료를
유지하며 Qt Core 이벤트 대기와 CTest로 실행한다.

입력 수명주기의 취소·큐·가짜 모델 검사는 Qt Test 없이 CTest로
실행하며 준비 대기 동안 Qt Core 이벤트를 계속 처리한다.

세션 초기화 검사는 셸을 사용하는 기존 사례와 플랫폼별 건너뜀을
보존한다. `session_clear_offline`은 셸 사례를 제외한 세 사례를 실행한다.
전체 사례가 건너뛰어지면 실행기는 CTest 건너뜀 코드 77을 반환한다.

권한 규칙 검사는 기존 10개 사례를 CTest로 실행한다. 셸 문자열은 실제
명령으로 실행하지 않고 구문 분석하며, 경로 교체 검사는 격리된 fixture 안의
파일과 링크를 사용한다. 플랫폼 조건이 맞지 않는 개별 사례는 건너뛴다.

노트북 검사도 Qt Test 없이 기존 12개 사례를 유지한다. 오프라인 선택은 Git
프로세스와 작업 트리를 사용하는 사례를 제외하며, 전체 검사와 오프라인
검사의 현재 작업 디렉터리를 fixture의 리소스 임시 경로로 지정한다.

권한 설정 갱신의 잠금·취소·동시 쓰기와 세션 권한 검사는 CTest에서 기존
사례와 플랫폼별 건너뛰기를 유지한다. 결과는 별도 Qt Test 출력 파일이 아닌
CTest의 표준 출력과 종료 코드로 보고한다.

작업 디렉터리의 권한·심볼릭 링크 경계 검사는 CTest로 실행한다. 오프라인
선택은 셸과 검색 도구를 실행하는 사례를 제외하고 격리된 파일 경계 사례를
검사한다. 플랫폼에 없는 링크 사례는 건너뛴다.

질문 수신함과 네이티브 뷰모델 검사는 CTest에서 요청별 신호 인자와 취소,
동시 요청 및 직접 MCP 호출 사례를 유지한다. 현재 작업 경로는 fixture가
관리하는 리소스 임시 공간이다. 각 사례가 끝나거나 실패할 때 보류된 Qt
지연 삭제 이벤트를 처리해 객체 수명주기를 유지한다.

메모리 추출 검사는 11개 사례와 플랫폼 건너뛰기를 유지하고 Qt Test 없이
CTest로 실행한다. 오프라인 선택은 실제 셸을 실행하는 사례를 제외하며,
가짜 모델을 사용하는 단일 사례도 별도로 선택할 수 있다. 임시 파일은
리소스 fixture에 두고 사례별 Qt 지연 삭제를 처리한다.

세션 종료 검사는 기존 11개 사례와 사례별 지연 삭제 처리를 유지한다.
오프라인 선택은 실제 명령을 실행하는 두 사례를 제외하고 가짜 모델과
인프로세스 API·취소 동작을 검사한다.

사용자 질문 검사는 12개 기능 사례와 입력 검증 데이터 20행을 유지한다.
콜백에서 관찰한 채널 소유권과 승인 결과는 콜백을 빠져나온 뒤 검증하며,
사례별 지연 삭제와 인프로세스 가짜 모델을 사용한다.

플러그인 스냅샷·의존성·모델·인프로세스 API 검사는 CTest로 실행한다.
오프라인 선택은 서버 설정·LSP/MCP 프로세스·명령 훅·CLI 사례를 제외하고,
시험 패키지와 상태를 fixture의 리소스 임시 공간에 둔다.

LSP 검사의 기존 12개 사례는 CTest 실행기로 이전하고 임시 Git 작업 공간을
리소스 fixture에 둔다. 검사는 Git과 LSP fixture 프로세스를 실행하므로 별도
요청 시 실행한다.

GraphQL의 기존 네 통합 사례는 CTest 실행기로 유지한다. 로컬 HTTP 서버, 셸,
MCP 및 데몬·CLI 실행을 포함하므로 별도 요청 시 실행하며 임시 상태는 리소스
fixture에 둔다. Unix 소켓은 별도의 짧은 개별 리소스 디렉터리를 사용한다.

작업 트리의 기존 14개 검사는 CTest 실행기로 유지하며 fixture는 리소스
작업 공간에서 격리한다. Git과 셸 프로세스를 사용하는 통합 검사는 별도
요청 시 실행한다.

웹 요청의 기존 10개 통합 사례는 CTest 실행기로 유지하고 아티팩트는
리소스 fixture에 둔다. 로컬 HTTP 서버를 사용하는 검사는 별도 요청 시
실행한다.

MCP HTTP 서버의 다섯 동시성·인증·취소 사례는 CTest 실행기로 유지한다.
로컬 HTTP 서버를 여는 통합 검사는 별도 요청 시 실행한다.

MCP HTTP 클라이언트의 12개 사례는 초기 Python fixture 확인과 TLS 도구가
없을 때의 건너뛰기를 보존한다. HTTP peer와 인증서 생성 프로세스를 사용하는
통합 검사는 별도 요청 시 실행한다.

에이전트 HTTP·IPC 전송의 기존 여섯 사례는 CTest 실행기로 유지하고
fixture는 리소스 작업 공간에 둔다. 로컬 서버와 소켓을 사용하는 통합
검사는 별도 요청 시 실행한다.

MCP 도구 출력 훅의 기존 12개 사례는 플랫폼별 컴파일 조건과 외부 효과
취소 검사를 보존한다. 로컬 MCP/HTTP 서버와 명령 훅을 사용하는 사례는
별도 요청 시 실행한다.

HTTP 훅의 기존 11개 사례는 CTest 실행기로 유지한다. 로컬 HTTP 서버와
일부 명령을 사용하는 통합 검사는 별도 요청 시 실행하며 임시 상태는
리소스 fixture에 둔다.

셸 작업의 기존 10개 사례는 데스크톱 및 Windows 건너뛰기 조건과
종료·복구 검사를 유지한다. 실제 셸 프로세스를 실행하는 통합 검사는 별도
요청 시 실행하며 임시 작업 공간은 리소스 fixture에 둔다.

세션 압축의 기존 12개 사례는 CTest 실행기로 유지한다. 이전 버전 전사와
잘린 체크포인트의 복구 사례는 외부 서비스 없이 독립 실행할 수 있으며
임시 전사는 리소스 fixture에 둔다.

로컬 애플리케이션의 기존 아홉 사례는 데스크톱 POSIX 조건과 CTest
건너뛰기를 유지한다. 객체 스레드·수명 사례는 서버 없이 별도 선택할 수
있으며 등록·서버 통합 검사는 별도 요청 시 실행한다.

도구 탐색의 기존 12개 사례는 CTest 실행기로 유지한다. 키워드·직접
선택 검사는 외부 서버 없이 별도 실행할 수 있으며 MCP 서버와 외부 peer를
사용하는 통합 검사는 별도 요청 시 실행한다.

명령 훅의 기존 14개 사례와 비동기 훅의 기존 19개 사례는 CTest 실행기로 유지한다. 기존 Unix 플랫폼 제한과 대기 시간을 보존하며 임시 파일은 테스트 리소스에 둔다. 이 훅 사례는 실제 명령 실행이 필요하므로 오프라인 구조 검사와 빌드를 별도로 수행한다.

서비스 모델의 기존 14개 사례는 각 사례의 초기화와 정리를 보존한 CTest 실행기로 유지한다. 가짜 런타임을 사용하며 QtTest 링크 없이 검증한다.

에이전트 엔진의 기존 21개 사례는 기존 선언 순서와 큐 정리를 보존한 CTest 실행기로 유지한다. 스키마와 등록기 검사는 외부 프로세스 없이 별도로 실행할 수 있다.

GraphQL 내장 HTTP 경로는 iiNetwork를 사용한다. 응답 파싱과 전송 정책의 헤드리스 검사는 가짜 응답을 사용하며 서버를 열지 않는다. 실제 HTTP 통합은 별도 실행 검증이 필요하다.

에이전트 API의 기존 19개 사례와 하위 에이전트의 기존 23개 사례는 운영체제별 건너뛰기와 각 사례 사이의 지연 삭제 처리를 유지한 CTest 실행기로 옮긴다. 명령 실행이 포함된 사례는 별도로 실행한다.

GraphQL 전송 테스트는 iiNetwork 전송 인터페이스에 가짜 구현을 주입해 정상 완료, 접수 실패, 취소와 조기 종료 시 콜백 정리를 확인한다.

에이전트 권한 조회와 잘못된 자식 분기 요청은 네트워크와 하위 프로세스 없이 개별 CTest로 확인할 수 있다.

MCP 세션의 기존 27개 사례는 CTest 실행기로 유지하고 운영체제별 건너뛰기와 임시 리소스 격리를 보존한다. 서버 세션과 셸 작업을 포함한 전체 사례는 별도의 실행 요청이 필요하다.

작업 보드의 기존 15개 사례는 Windows 전용 5개와 자식 프로세스 작업 모드를 보존한 CTest 실행기로 옮겼다. 검증 콜백의 상태 확인은 호출 후 검사하며, 외부 프로세스 없이 유니코드 소유자 저장 사례를 따로 실행할 수 있다.

MCP 표준 입출력 검사의 기존 14개 단일 사례와 잘못된 프레임 5개 데이터 행을 CTest 실행기로 유지한다. 공통 실행기는 사례 이름으로 모든 데이터 행을 선택하거나 전체 행 이름으로 하나만 선택할 수 있다. 진행 콜백의 메시지는 콜백 밖에서 확인한다.

에이전트 훅의 기존 13개 단일 사례와 실행 횟수·권한 모드·바이트 한도의 데이터 행 7개를 CTest 실행기로 유지한다. 외부 명령 없이 가짜 실행기로 훅 설정 중복 처리를 확인하는 사례를 따로 제공한다.

계획 모드의 기존 22개 단일 사례와 네 데이터 행을 CTest 실행기로 유지한다. 검토·실행 경계 콜백에서 수정한 파일의 기록 성공은 콜백이 끝난 뒤 검사하며, 명령 실행 없이 권한 제한을 확인하는 사례를 제공한다.

팀 테스트의 기존 23개 단일 사례와 메시지 스키마·자동 할당 데이터 행 14개를 CTest 실행기로 유지한다. 메시지 스키마의 12개 행은 외부 서버나 명령 없이 그룹으로 선택해 확인할 수 있다.

입력 큐의 기존 23개 단일 사례와 배치 한도 데이터 행 2개는 CTest 실행기로 유지한다. Windows 전용 4개 사례와 별도 큐 게시 작업자 모드도 보존하며, 큐 순서·한도·복원은 외부 프로세스 없이 확인할 수 있다.

선택형 레거시 질문 화면의 여섯 사례는 CTest 실행기와 QtGui의 창 입력 이벤트로 유지한다. 클릭 좌표·입력·Escape·대기 시간 및 테스트별 임시 리소스를 보존하며, QtTest를 링크하지 않는다. 이 화면 검사는 GUI 실행이 별도로 허용된 환경에서 검증해야 한다.

에이전트 전송 검사의 각 사례는 상태 작업 공간과 별도로 `resources/` 바로 아래 고유한 IPC 작업 공간을 사용한다. 짧은 소켓 경로로 플랫폼의 로컬 소켓 경로 길이 제한을 지키며, 서버 종료 후 해당 사례의 임시 디렉터리만 정리한다.

에이전트 전송 여섯 사례는 전체 실행 외에도 각각 CTest에서 선택할 수 있다. 소켓 작업 공간과 리슨 성공 경로를 출력해 강제 종료 시 소유 작업 공간과 진행 위치를 구분한다.
