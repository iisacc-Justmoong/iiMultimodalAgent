# 문맥 수용과 선제 압축

압축의 triggerFraction은 선제 작업을 시작할 기준이며 모델 문맥의 두 번째 하드
한도가 아니다. 새 요청이 출력 예약을 포함한 실제 문맥 한도 안에 있고 압축할
오래된 완결 그룹이 없다면 그대로 생성한다. 수동 압축과 실제 초과의 오류는 유지한다.

회귀 검사는 같은 4,096 문맥과 64 출력 예약에서 선제 기준 위·하드 한도 아래인
새 요청이 압축 없이 완료되는지 확인한다. 같은 설정에서 실제 한도를 넘는 요청의
실패도 확인한다. 기존 압축 그룹·도구 결과의 원자성·원문 보존 계약은 바꾸지 않는다.
## 도구 스키마의 예산

네이티브 토큰 측정값이 출력 예약을 포함한 실제 컨텍스트 한도를 넘고 도구 검색이 활성화된 경우, 해당 턴의 독립적인 레지스트리 사본을 지연 검색 방식으로 전환한다. 실행 핸들러와 권한·검증은 그대로 보존하고 ToolSearch로 필요한 정의를 선택한다. 사용자 대화가 아닌 전체 도구 스키마를 대화 요약으로 줄이려다 첫 요청이 거절되는 문제를 방지한다. 호스트가 검색을 비활성화했거나 자체 ToolSearch를 제공한 경우 이 전환은 적용하지 않는다. 전역 레지스트리와 모델 컨텍스트 크기는 변경하지 않는다.



도구 카탈로그를 지연 검색으로 전환할지는 대화 이력을 제외한 기본 요청의 실제 토큰 예산으로 판단한다. 오래된 대화가 넘치는 경우에는 기존 압축 절차를 사용하므로, 압축 전에 현재 실행의 스킬 도구가 제거되지 않는다. 스킬 권한의 실행 간 만료 규칙은 변하지 않는다.


네이티브 카탈로그 측정 요청은 호스트 컨텍스트와 최신 사용자 입력부터 현재 완료된 도구 결과까지의 대화 구간으로 구성한다. 이전 대화 이력은 카탈로그 크기로 계산하지 않으며, 사용자 입력이 필요한 네이티브 대화의 끝 경계를 유지한다. 이 측정용 요청으로 실제 생성 요청의 원본 이력을 교체하지 않는다. 사용자 입력도 호스트 컨텍스트도 없는 경우에는 카탈로그 전환 측정을 건너뛰고 기존 실행·압축 계약을 따른다.

## API 실행 승인과 세션 읽기

`agent.run`, 대기 입력 실행, 압축의 사전 승인은 인증된 클라이언트의 세션 헤더로
작업 공간을 확인한다. 실제 실행은 세션을 한 번 독점 확보하고 전체 전사 체인과
레코드를 검증한 뒤 같은 스냅샷으로 실행 문맥을 구성한다. 승인 단계에서 전체
전사를 읽고 잠금을 해제한 다음 다시 읽던 중복 I/O를 제거한다. 원본 요청 마감
시간, 헤더·작업 공간 검증, 손상된 전사 거절, 원자적인 저장 규칙은 유지한다.
`runAdmissionStillValidatesTranscriptBody`는 올바른 헤더 뒤의 손상된 레코드를
모델 진입 전에 거절하는지 검증한다.
